# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What This Is

DIR.Lib is a Device-Independent input + Rendering library for .NET — the shared foundation for GPU (SDL3+Vulkan), terminal (Console), and browser (WebGL2 / Blazor WebAssembly) SharpAstro applications. It provides platform-agnostic rendering primitives, a widget system with hit testing, input handling, a signal bus, and a pure-managed font rasterizer (no native dependencies).

## Build & Test Commands

```bash
# Build (solution lives at the repo root)
dotnet build DIR.Lib.sln

# Run all tests
dotnet test --project src/DIR.Lib.Tests

# Run a single test
dotnet test --project src/DIR.Lib.Tests --filter-method "*TestMethodName"

# Run tests in a specific class
dotnet test --project src/DIR.Lib.Tests --filter-class "*RenderAcceptanceTests"

# Regenerate visual baselines (only after investigating failures)
DIR_LIB_UPDATE_BASELINES=1 dotnet test --project src/DIR.Lib.Tests --filter-class "*RenderAcceptanceTests"
```

`--filter-class` matches the full class name (`DIR.Lib.Tests.FooTests`) or a wildcard (`*FooTests`); a bare class name
matches nothing, MTP exits 8 ("Zero tests ran") and a leg check fails with no failing test named (issue #283).
A filter that matched nothing already exits 8; `--minimum-expected-tests N` also fails a run that ran fewer than N tests.

CI runs tests in Release config after building, before publishing NuGet packages.

**Tests run on Microsoft.Testing.Platform (MTP), not VSTest** (since 11.1). The runner is declared in
the root `global.json`, which pins no SDK; each test project is an `Exe` on xunit.v3 4.x, with no
`Microsoft.NET.Test.Sdk` or `xunit.runner.visualstudio`. `--filter` with a VSTest expression still works
(`--filter "FullyQualifiedName~MenuPanelTests"` runs that class, and an expression that matches nothing exits 8), beside
xunit's own `--filter-class` / `--filter-method` / `--filter-namespace`; this page once said it fails, which no run
showed (issue #285). The other VSTest options do fail the run: use `--output Detailed` for `--logger "console;verbosity=detailed"`, `--report-trx
--report-trx-filename x.trx` for a TRX logger, `--crashdump` / `--hangdump --hangdump-timeout 5min` for
`--blame-*`, and `--minimum-expected-tests N` to fail a run that ran fewer than N tests. A stale VSTest
option fails the run as unknown rather than collecting less. **Both test projects reference the same
three extensions (TRX, crash dump, hang dump), and must go on doing so**: a solution-wide `dotnet test`
passes every option to every project, so one project without `--hangdump` made the whole run exit 5 with
"zero tests ran" for that project while the other passed.

## Architecture

**Namespaces:** Core types live in the root `DIR.Lib` namespace. Two sub-namespaces host larger subsystems:
- `DIR.Lib.MathLayout` — TeX-style box model (`Box`, `BoxStyle`, `BoxRasterizer`, and the per-construct boxes: `FracBox`, `SqrtBox`, `BracketBox`, `BigOperatorBox`, `SupSubBox`, …).
- `DIR.Lib.Markdown` — markdown / LaTeX pipeline (`MdAst`, `MarkdownBlockVisitor`, `MarkdownInlineVisitor`, `LatexUnicodeVisitor`, `BoxBuildingVisitor`, `Mhchem`, `MarkdownMacros`). Public since 4.1; no friend-assembly grants needed.

**Core abstractions:**
- `Renderer<TSurface>` — abstract generic renderer; backends (SDL/Vulkan, Console) implement this in downstream repos. Provides default polyline + dashed-line implementations on top of the abstract rect / ellipse / text primitives.
- `RgbaImageRenderer : Renderer<RgbaImage>` — pure software renderer used in tests and headless scenarios
- `IWidget` / `IPixelWidget` — widget interfaces with input handling and hit testing
- `PixelWidgetBase<TSurface>` — base class for pixel-based widgets, manages clickable regions, drawing helpers, text inputs
- `InputEvent` — abstract record hierarchy (open discriminated union): `KeyDown`, `TextInput`, `MouseDown`, `MouseUp`, `MouseMove`, `Scroll`, `Pinch`, `PinchEnd`
- `HitResult` — open record hierarchy for click dispatch: `TextInputHit`, `ButtonHit`, `ChromeHit`, `LinkHit`, `ListItemHit`, `SlotHit<T>`, `SliderStateHit`
- `SignalBus` — thread-safe typed event bus; `Post<T>()` is thread-safe, `ProcessPending()` runs on render thread
- `DockLayout<T>` — generic dock layout engine using `INumber<T>`
- `ManagedFontRasterizer` — pure-managed glyph rasterizer (AOT-compatible) backed by `SharpAstro.Fonts.OpenTypeFont`; supports COLRv1 color glyphs, grayscale, and PDF subset fonts
- `FontResolver` — platform-default monospace lookup + cross-platform installed-font enumeration (including Win11 per-user font dir)
- `FontFallbackResolver` — coverage-driven font runs for UI text. Faces declared by role (`FromRoles`) also get Unicode's default presentation applied: a pictograph goes to the emoji face even where the primary covers it (U+2615 is the case that found it), while text-default marks (✓ ★ ⚠ ❄, arrows) stay on the primary
- `EmojiPresentation` — the `Emoji_Presentation` property behind that. **The data half is GENERATED**: `dotnet run` in `tools/gen-emoji-presentation` rewrites `src/DIR.Lib/EmojiPresentation.Data.g.cs` from unicode.org's `emoji-data.txt`. Re-run it per Unicode release; never hand-edit the table
- `CanvasViewport`: a zoom, pan and fit viewport over a canvas of design units (pilot's `MapViewport` generalised). It sits BESIDE `PanZoomController`, composing one for the drag and cursor-anchored zoom, because it owns the content size and so computes the fit, the keep-in-view clamp and the design/view mapping. `HandleInput(evt, bounds, leftDragPans)` is the gesture handler (Ctrl+wheel via `ZoomByWheel`, `ZoomStep^delta`; pinch; middle or Space+left pan; zoom/fit/pan keys, Up/Down only with `PanWithVerticalKeys`) and returns whether it took the event
- `MenuLayout.BuildPanel` / `PlanPanel` (11.69), `PixelMenuWidget.RenderPanel()`: the menu as a modal `Overlay` (full-surface scrim, centred card). `PlanPanel` sizes the card in design units through an `IMeasureContext<float>`: content width clamped to `MenuPanelStyle.MinWidth`..`MaxWidth`, full width less `SideMargin` when portrait, font = `FontToCard` of the card capped so the widest line (title 1.6x, the `▶` row) fits. Rows and key declarations come from the same private `BuildColumn` as `BuildTree`; the card edge is a declared `Node.BorderStyle`. `Render()` is untouched. `BuildPanel` makes the column `Star` wide (11.87): the card is often wider than its content (short menus, every portrait card), and a content-sized column sat at its left edge; `MenuPanelRenderTests` pins a wide and a narrow baseline
- `ListCursor` — the keyboard's position in a list the layout tree already declares, and the counterpart of `PixelWidgetBase.Pointer`: both resolve against the regions the last paint registered, so the rows the arrows reach and the rows a click reaches are one list. A row needs no state of its own — `ListItemHit(list, index)` is the whole declaration, and a row that is not `.Clickable` registers no region and so cannot be reached. `HandleListKey` claims Up/Down/Enter and nothing else; Escape stays with the widget
- `IMeasureContext<T>.MapExtent(in ExtentRequest)` (11.63): the extent hook. Every Fixed extent and padding the engine resolves (measure and arrange alike, through one helper in `Engine.cs`) goes through it with the authored value, axis, `ExtentKind` Fixed/Padding, and whether the node holds text (`HasContent`, `ContentLines`) or a fill (`HasFill`). The default is `ToSurfaceX`/`ToSurfaceY` of the value, so a context that ignores it arranges as before (`LayoutArrangeSnapshotTests` pins that); gaps, margins, Box/Icon content and anchored offsets stay on `ToSurface*`. The request is an init-only record struct so a later field is additive
- `Layout.Node.Wrap.FirstLineTrailing` (11.65), set with `WithFirstLineTrailing(node)`: a node drawn flush at the main end of the FIRST line only, whose main extent is MEASURED (Fixed through `MapExtent`, Auto by the surface context), so line 1 reserves that extent plus a gap and lines 2+ use the full extent. It replaces a hand-computed `FirstLineReserve`, which is in design units and wrong in cells. If the first item does not fit beside it, line 1 holds only the trailing node and the items start on line 2; `FirstLineReserve` adds space between the two, and `MaxLines` always keeps the trailing node. `MeasureWrap` and `ArrangeWrap` honour it identically
- `WindowUiSettings.CaretPhase` (11.84): the caret blink phase, once per window beside `CaretRect`. The host's frame loop sets it once per frame from `CaretBlink.PhaseAt(TimeProvider)`; `PixelWidgetBase` draws inputs from `Ui.CaretPhase`, and `PixelWidgetBase.CaretPhase` only forwards to it (a child sharing the parent's `Ui` shares the phase)
- `DeclaredList` (11.61): `Layout.Node.ListOf(cursor, listId)` declares the `ListCursor` that owns a list's rows on its container. `DeclaredList.Active` is the one active-list rule (focused list, else last pressed, else the only one on the frame, else none), and `InputRouter` steps that cursor for any `IPixelWidget`, pixel or not. `IPixelWidget.CollectClippedListRows` reports rows a viewport clips, and `IPixelWidget.RevealListRow` (default empty) is called after the router steps a declared list so a list under `WithScroll` scrolls to the row the arrow lands on. `IPixelWidget.RevealListEdge` (11.90, default false) is called when NO row can take the cursor: a scrolled stack lays out only the rows near its viewport, so a run of disabled rows taller than that margin left the arrows with nowhere to go; the surface scrolls the farthest row it holds that way into view and answers whether the list moved, which is the difference between "more list" and "the end". A non-pixel surface carries a popover's pointer claim with the public `WindowUiSettings.NoteFrameBegin` / `NotePopoverPainted` / `ClaimPointer`
- `InputRouter`: the frame's input dispatcher, so a host writes none. `Handle(evt)` walks the regions, fields, shortcuts, drag captures and scroll controllers the last paint declared, in one fixed order, and `AfterPaint()` applies the three rules that need a finished frame (blur an unpainted field, answer a `focusOnOpen` request once, expire a stale tooltip). The rule to know before touching it: a key reaches a declared `Layout.Node.Shortcut` ahead of a focused text field only when `KeyChord.BeatsFocusedField` says so, and a shortcut is matched against the PAINTED tree, never the arranged one. A host keeps its platform binding (`FocusChanged`, the clipboard) and its own `Unhandled`
- Declared modal routing: `Layout.Node.Overlay.Modal` / `OnDismiss` (init-only), built with `Builder.Modal(layer, top?, onDismiss)` (a null top is the modal closed, so the tree is the open state). The painter records the painted Top in `WindowUiSettings.PaintedModal` (`NoteModalPainted`, cleared per cycle like `PaintedPopovers`; a non-pixel surface calls it itself). `InputRouter` then sees only Top: every region and node it reads goes through `CollectRegions` / `CollectNodes`, which drop widgets painted before the modal's and the modal widget's own Base, so presses, shortcuts, declared lists, scroll and drags cannot reach Base. A press Top does not take is consumed and, outside the card, runs `OnDismiss`; Escape runs it too; a key Top does not take is consumed, not handed to `Unhandled`. `ModalClaim.RegionEnd` / `NodeEnd` close the claim where Top's subtree ends, so an inline modal (a `ConfirmStrip` in a column) does not cover rows painted after it. The rule lives in one block of `InputRouter` ("declared modal")
- `TextSelection<TSurface>` — drag-select, highlight and copy for raster hosts. A widget opts in with `PixelWidgetBase.WithSelection(page)`, which lays a Fill leaf over the page that `PaintLayout` paints itself; `InputRouter` reaches it through `ITextSelectionHost` (never an `IPixelWidget` member) and routes the drag, Ctrl+C (with no focused field) and the right-click (`OpenSelectionMenu`). A press only starts a selection where the topmost painted region is plain chrome and no popover owns the pointer
- `FloatingPalette`: a floating, grip-dragged, collapsible palette of toggle rows: a `Layout.Node` tree plus the pure rules around it (`FloatingPaletteState`, `PaletteItem`, `PaletteColors`). `Build` returns the tree and touches no surface, so a palette's geometry and its click bindings are testable with a stub measure context and no GPU. The overload taking a `DesignScale` declares the grip's drag (a `DragCapture`), the double-press collapse (`DoubleClickable`) and the panel's claim on the pointer; prefer it, since the `onGripPress` one leaves all three to each host. `NoteArranged` must be called back every frame, or the clamp and the consumer's offset diverge silently
- `DIR.Lib.Notifications` (11.83): `NotificationFeed` is the surface-neutral model (the clock is passed in, no timers), and `NotificationsLayout.Build` declares the bell, the side bar (an overlay over the right of the page when open, a narrow strip holding the bell when collapsed), the toasts and the list as one `Layout.Node` tree that a float and an int measure context arrange alike. The toast stack sits at `NotificationsStyle.Corner` (default bottom right, newest nearest the corner) and never moves with the pointer (11.86); `Build`'s `pointer`/`contentRect` overload compiles and ignores both. Every toast card and the open bar are surfaces (`Node.IsSurface`). Since 11.88 a toast is tinted by severity (`NotificationsColors.TintedFill`/`TintedEdge`), with a 1-unit edge, radius 6, `Shadow`, an 18-unit icon, and a Close cross (`NotificationPart.Close`) on a fading card; the public `PrimaryButton`/`PlainButton` builders are shared with the bar's rows, and a one-hue palette drops tint and shadow. Since 11.91 a staying `Notification` may carry `Buttons` (init-only `Func<IReadOnlyList<Layout.Node>>`, evaluated each build like `Row`): the host's own buttons, built with `PrimaryButton`/`PlainButton`, are drawn after the action and before Dismiss in one right-aligned row while they fit (they wrap onto further rows past the card, 11.94), and Dismiss is plain whenever an action or any host button is present. Since 11.95 `NotificationsLayout.BuildList(feed, state, colors, style)` is the list frame alone (header with Clear, scrolled Needs you and History, `WStar`/`HStar`, not a surface) that the open bar is built from, for a host with a page of its own; `NotificationsStyle.StripWidth <= 0` makes `Build` leave the strip out (the `ToggleKey` shortcut lives on the strip), and a word of 16 characters or more breaks after `\ / | , ; = & - _ .` (never at a `.` or `,` inside a number; shorter words stay whole), and any leaf still wider than its line ends in an ellipsis. `NotificationsRenderTests` pins pixel baselines (dark, light, one-hue, wide and narrow) and cell snapshots
- `Layout.Node.IsSurface` (11.86), set with `AsSurface()`: what is painted over something takes the pointer from it. Within the surface's rect nothing painted before it (earlier in the tree or in a widget beneath) gets hover, tooltip, cursor, press, release click, double click, context menu or wheel; what it contains works as ever. The painter registers a region over the whole rect marked `ClickableRegion.IsSurface`, where every `InputRouter` walk stops (a surface is never inert chrome; the wheel over it is consumed; a capture-less release still reaches `Unhandled`). Paint-time hover cannot see a later surface, so it rides the popover claim's carry: `WindowUiSettings` notes surfaces with their paint order (`NotePaintedNode`, `NoteSurfacePainted`, `IsCoveredBySurface`), carries them a cycle, and `PointerClaimSettled` folds them in so the first frame of a new surface asks for one more. Widgets that share no settings are covered too: `InputRouter.AfterPaint` lays each listed widget's surfaces onto the settings of the widgets painted before it (bounded by paint order, so a widget painted after the surface still lights), since only the router's list knows the paint order of all of them; a test of the cross-widget rule must run with unshared settings as well, or `ShareWith` hides that path. Declared, never inferred from a background, so a tree changes only when it says so. Console.Lib's cell painter does not register surfaces yet
- `Layout.Node.Shadow` (11.88), set with `Shadow(ShadowStyle)`: a declared drop shadow under the node's rounded rect; cells paint none and give it no cells
- `Layout.Node.FocusRing` (11.98), set with `WithFocusRing(color, width, offset)`: a `FocusRingStyle` stroke drawn OUTSIDE the node's rounded edge while the list cursor is on its hit, never for a disabled node, taking no layout space. The pixel painter draws it after the border; it is in `LayoutDamage.PaintSignature` and `DamageRect` grows by it. Button, Chip, SplitButton and ToggleTile declare it from `UiPalette.Focus` and `UiMetrics.FocusRingWidth` (default 2) and `UiMetrics.FocusRingGap` (default 2, a gap so the ring shows on an accent fill; `FocusRingStyle.Offset`) instead of `BgFocus`; `FocusRingStyle.Sides` leaves out a side (a split button part's inner side), the ring staying rounded and clipped flat at the node's edge; list rows keep `BgFocus`. Cells draw no ring yet
- `Layout.Node.NarrowForm` (11.89), set with `OrWhenNarrow(node)`: the form a node takes when its full form does not fit the room it is given. The engine measures the full form and swaps the narrow one in whole, identically in measure and arrange, for float and int (cell) contexts
- `UiTheme.Controls` / `Builder.Button` / `Builder.Hyperlink` (11.93): the themed button and link, drawn from `UiTheme.Controls` alone (`ControlStyles` of `ButtonStyle` Accent/Standard/Subtle and `HyperlinkStyle`, derived from the palette's `ControlFill*`/`ControlEdge` roles and `UiMetrics.ControlRadius`), so a restyle is one `with` on the theme. Hover, pressed (`Node.BgPressed`) and focus are declared fills, a disabled button is flat with its reason as tooltip, `opens` adds a trailing `›` chevron text leaf (the `CaretRight` icon until 11.104), `external` adds a north-east arrow. `ControlLiteralInvariantTests` fails on `new RGBAColor32(` in `Button.cs`, `Hyperlink.cs` and `ControlStyles.cs`
- `Builder.Segmented` (11.89): a themed one-of-few control from `UiTheme` only; each segment is icon and word, and every word drops at once (through `NarrowForm`) when the control does not fit. Left/Right move the choice when it has the keyboard (a horizontal `DeclaredList` with `SelectOnStep`), segments take shortcuts, a disabled segment says why. DSN-1 v4 look: one rounded `HeaderBg` track, the chosen segment a `SeparatorStrong` pill in `BodyText` (never the accent), the others `DimText` with a faint `Separator` pill on hover; the track is ringed with `Focus` while its declared list holds the keyboard (`WindowUiSettings.KeyboardListId`, published by `InputRouter`), and an overload taking `lockedReason` dims it whole
- `Builder.Switch` (11.104, DSN-1 v4 in 11.105): ONE switch with two overloads, both drawn from `UiTheme.Controls.SwitchOrDerived` (`SwitchStyle`) alone. The 11.104 overload `(on, onChange, theme, label, labelBefore, disabledReason, tooltip, hit)` is published and keeps its signature and geometry (`HeightScale`/`WidthScale`/`KnobInset` of `ButtonHeight`, the label part of the hit, Space and Enter through `Activatable`). The sized overload `(on, onToggle, theme, SwitchSize size, stateLabel, lockedReason, changing, refusedReason, asking, tooltip, hit)` takes `SwitchSize` Regular 40x22 knob 18 or Small 30x16 knob 12, required so `Switch(on, f, theme)` still binds the 11.104 one. `ControlStyles.For` gives both the DSN-1 v4 colours from palette roles (`SwitchStyle.For`): on is the `Accent` track and off a `HeaderBg` track with a `SeparatorStrong` edge, so on and off differ by knob side and fill, never by colour alone; the v4 states are init-only optional `SwitchStyle` members (`OffHoverKnob`, `OffKnobEdge`, `Locked*`, `RefusedEdge`, `AskingRing`) read through their `*OrDerived` accessors, so a style written against 11.104 compiles. On the sized switch only the track is the hit (`ButtonHit("switch")` unless `hit` says), never its optional `stateLabel`; hover is a declared fill (the off knob lightens with it through `Node.HitHoverBackground`), keyboard focus a `FocusRing`, `lockedReason` dims it and keeps the knob's side, `changing` parks the knob in the middle and takes no press, `refusedReason` gives an `Error` edge and a tooltip, and `asking` rings it in `Warn` while a caller's own question is answered. The sized switch reserves room for the ring on every side so asking never moves the layout. A press calls the handler with the NEW value; the caller flips at once and sets it back when refused. The slide is `Node.Knob` (`KnobSlide.Switch`), on both overloads: `WindowUiSettings.NoteKnob` keeps the side per knob and the pixel painter eases it over `MotionClock.KnobSlideMilliseconds`, so the builder stays stateless; locked and `ReducedMotion` land at once. `SwitchRenderTests` pins the 11.104 overload (`switch_states_dark.png`, `switch_states_light.png`), `SwitchControlTests` the sized one (`switch_v4_states_dark.png`, `switch_v4_sizes_themes.png`)
- `WindowUiSettings.MotionMilliseconds` / `ReducedMotion` / `IsMoving` and `IconKind.Spinner` (11.105): the motion clock, once per frame beside `CaretPhase`, set by the host from `MotionClock.MillisecondsAt(TimeProvider)`. The spinner (an accent arc turning on a `SeparatorStrong` ring, slower under `ReducedMotion`) and the knob slide read it, so a frame nobody drew advances nothing and a test sets a fixed value. A knob whose clock does not move lands on its new side at the next cycle. `LayoutDamage.PaintSignature` carries no motion, so `IsMoving` overrides a host's empty-damage repaint gate. `IsMoving` is true while something painted this cycle moves; a host asks for another frame while it is up, so an idle window costs none. Each icon kind needs a glyph in `IconGlyphs.For` and Console.Lib's `EveryIconKindHasAGlyph` must name `Spinner` (a consumer flight)
- `Builder.ConfirmStrip` / `Builder.ConfirmChoices` / `ButtonKind.Destructive` (DSN-1 v4 confirm): the first press of a wrapped button turns it, in its own place, into a question with the confirming button after it and Cancel last (the strip keeps the rest button's right edge, so the confirming button is never under the first press). A caller-held `ConfirmState` owns the asking state; Escape and a press elsewhere cancel (the strip is a declared `Modal`), the confirming button holds the keyboard (a horizontal declared list), and the second press of a double-click never confirms. `Consequence.Destroys` is `Error`, `Hazard` is `Warn`. `ConfirmChoices` is the form placed under a row (Warm, then off; Off now; Cancel), empty and taking no room while not asking. A destroying action's rest look is its label in `Error`
- `Builder.BusyButton(label, busyLabel, BusyState, estimate, onStop, onStart, theme, ...)` (DSN-1 v4 busy): a long task's button drawn in the state the caller passes (`BusyState.Rest`/`Busy`/`Overdue`/`Stopping`/`Done(result)`/`Failed(reason)`; nothing here is a timer, `BusyState.HoldsDone` takes the clock as an argument). Busy keeps the button's place and size with the spinner before the verb in `DimText`; where the task can be stopped (`onStop` not null) a Stop segment grows out of the LEFT edge, joined by a hairline inside one rounded edge, neutral and `Error` on hover, so a double-click cannot stop what it just started. The estimate sits left of the whole control and turns `Warn` past it. Stopping folds the segment away; Done shows a `Success` tick with the result, Failed rests again with the reason in `Error`
- `Builder.ButtonGroup` equal-to-widest (11.106): `ButtonGroupStyle.EqualToWidest`, `ButtonGroupStyle.SegmentPadding` and `ButtonGroupOption<T>.WidthSample` (all init-only) make every segment as wide as the widest option's measured content (`WidthSample`, else label, else icon) plus the padding either side, so the group has an intrinsic width and sits at Auto width in its row. A set `SegmentWidth` wins. The mode returns a one-row `Grid`; every other group builds the tree it always did. `ButtonGroupRenderTests` pins `button_group_equal_to_widest.png`
- `Builder.Segmented` restyle (11.105): the existing signature stays for binary compatibility and now draws the DSN-1 v4 track (see the entry above); `ButtonGroup` is untouched and `Segmented` supersedes its look, so a restyle of a consumer's group is that consumer's adoption flight. An on/off pair is a `Switch`, not a two-segment control
- `Builder.SettingRow` with `SettingTrailing.Of(node)` and no `onClick` (11.105): the row registers no hit and takes no hover, pressed or focus fill, so only the trailing control is the hit (DSN-1's "only the switch flips the preference"); a row with an `onClick` behaves as before. `SwitchFamilyScreensTests` pins the settings and equipment screens as composed fixtures
- Prototype kinds `switch` (takes `bind`; `label`, `labelBefore`, `disabled` draw the 11.104 switch, and any of `switchSize` (since `size` is the dock extent), `stateLabel`, `locked`, `changing` the sized one), `segmented` (takes `bind`, `options`) and `busyButton` (`label`, `busyLabel`, `state`, `estimate`, `stoppable`, `result`) build through those builders; `prototype-format.md` documents them
- `Builder.Chip` / `Builder.SplitButton` / `Builder.ToggleTile` (11.96): the themed filter chip (`ChipStyle`; `ChipRow` steps it with Left/Right), the split button (two separate hits and a divider, the left part acts or toggles, the right opens details) and the toggle tile (`ToggleTileStyle`, an icon tile with its label under it that never squeezes the icon). All draw from `UiTheme.Controls` alone; `ControlStyles.Chip` and `Tile` are init-only and optional (`ChipOrDerived`, `TileOrDerived`), and `ControlLiteralInvariantTests` covers their sources
- `Builder.IconToggle` / `Builder.IconAction` (11.89): a square icon button from the SVG set. Pressed, a toggle fills with the accent and takes the filled form of its icon (`IconSet.FilledForm`: Pin to PinFilled, any other kind maps to itself); its words are its tooltip and an optional word beside the icon drops by the `NarrowForm` rule. `IconAction` is the same button with no pressed state
- `DeclaredList.Horizontal` / `SelectOnStep` (11.89), `Node.ListOf(cursor, id, horizontal, selectOnStep)`: a list along the row, which `InputRouter` steps with Left/Right instead of Up/Down; with `SelectOnStep` a step also acts on the row it lands on. Init-only, so the record's constructor keeps its shape
- SVG icon kinds (11.88): new `Layout.IconKind` members drawn from an SVG icon set; each needs one character in `IconGlyphs.For`, and Console.Lib's `EveryIconKindHasAGlyph` must name them
- `DIR.Lib.ChildWindows` (11.85): `ChildWindowSet` is the surface-neutral model of floating child windows in one host (front-to-back order, one active child, move, resize with `MinWidth`/`MinHeight`, close, `Cascade`/`Tile`/`ShowAsTabs`; geometry in design units against a host rect). The keep-reachable rule: a `KeepReachableStrip` of each title bar stays inside the host on every edge, and the title bar never leaves the top or bottom. `ChildWindowsLayout.Build` declares the set as one `Layout.Node` tree (each child an `Anchored` node in its own `Overlay` layer, title bar with marker, ellipsised title, the word "active" on the active bar, and close; drag; resize handles laid out as one engine layer, none over the close button; tabs through `TabStripTree`, whose empty strip swallows a press), and `Node.OnPressWithin` lets `InputRouter` raise the window under a press on a content control. Each window's `Anchored` sets `OffsetsPerAxis`, so its design-unit offsets map per axis on a cell surface; a cell host passes `ChildWindowStyle { TabRule = 0 }`. A maximised child fills the host; a minimised one is the host's to show. `ChildWindowsRenderTests` pins five pixel baselines and five cell snapshots
- `Prototype` (11.75, `DIR.Lib.Prototyping`): a prototype is a JSON document of screens that loads into real `Layout.Node` trees. `Prototype.Load(json)` returns the document or problems with JSON paths, `PrototypePlayer<TSurface>` plays it as an ordinary widget (clicks are `ClickableRegion`s, so `InputRouter` reaches them), `Prototype.Check(document, sizes)` draws each screen and each `when` state into a `WireframeRenderer` and returns `Wireframe.Check` findings by screen, state and size, and `Prototype.Render(document, size)` returns an `RgbaImage` per screen. Both take an optional `fontPath`; without one they resolve the platform face (`Prototype.ResolveFont`, through `FontResolver.ResolveSystemFont`) and throw when there is none, because with no font no text is measured or drawn and a check would pass a broken screen. A document may name `targets` (name, width, height, scale); the player sets a read-only `target` state (compact under 600 design units wide, else regular) a `when` can name, and `Check(document)` / `Render(document)` with no sizes run at each target (11.77), findings carrying `PrototypeFinding.Target`. The vocabulary is `src/DIR.Lib/Prototype/prototype-format.md`, held to the loader by a test. A number that measures something drawn (`PrototypeProperty.NonNegative`: padding, gap, font size, extents) is a load problem below zero (11.87), and the player sets its builder's `DesignSize` from its own before each build, so `target` cannot follow a size written on `TreeBuilder`
- `Builder.Switch` (11.104, see the switch entry above for the DSN-1 v4 overload) and the prototype workbench vocabulary: `Content.Text` takes `Weight` (bold) and `Face` (monospace); a node's hover-reveal flag shows it only while its row is hovered or selected. The prototype vocabulary uses them: `button` `style`, `switch`, `tree`/`treeRow`, `tabs`, `table`/`tableRow`, `hoverBackground`, `revealOnHover`, `selectedWhen`, `doubleAction`, text `weight`/`face`/`style`. `PrototypeShowcaseTests` (`Fixtures/Prototype/showcase.json`) is the end-to-end proof, with baselines in a dark and a light palette. Tree and table rows are declared lists (a `ListCursor` per container, `ListItemHit` rows, a focus ring), so Up, Down and Enter reach them; Enter runs a row's `doubleAction`, else its action, and reaches no other kind. `PrototypeFaces` (new `Check`/`Render`/`PrototypePlayer` overloads) gives bold and mono runs their own faces. Not yet sayable: keyboard focus on prototype buttons (no declared list reaches them), and a held press on an action that runs on the way down
- Text-stack footprint (11.107): `RgbaImageRenderer.GlyphCache` / `ManagedFontRasterizer.Footprint` / `SdfFontAtlas.Footprint` are allocation-free counters; `GlyphCacheMaxEntries`, `GlyphCacheMaxBytes` (renderer) and `IdentityMemoMaxEntries` (rasterizer) cap the caches through the internal `BoundedCache`, defaults unchanged and output byte-identical when capped. The tiny-app atlas recipe (512 page, 4 pages) is in the `SdfFontAtlas.DefaultInitialAtlasDim` doc comment
- `BoxRasterizer.RenderToRgba` (in `DIR.Lib.MathLayout`) — math-layout entry point; returns a raw `RgbaImage` so the caller picks the encoder (PNG / sixel / half-block / …)

**Key design constraints:**
- **An optional parameter added to a record's primary constructor is a BINARY break.** It is source-compatible, so it reads as additive and the compiler says nothing -- but the old constructor is gone from the assembly, and every already-compiled caller throws `MissingMethodException`. A positional PATTERN breaks too, at compile time in the consumer: a record's synthesized `Deconstruct` takes its arity from the primary constructor, so `Evt(var a, var b)` stops binding the moment a third parameter appears, defaulted or not. So such a change is either a MAJOR, or it ships with an **explicit old-arity constructor AND an explicit old-arity `Deconstruct`**. 9.1 learned this the expensive way: it added `TextInputGeometry Painted = default` to `HitResult.TextInputHit`, called the release "additive throughout", and the published Console.Lib (which calls the one-argument form in `CellLayout.HitOf`) threw on every terminal hit test. It was invisible on a dev box, where `UseLocalSiblings` compiles the sibling from source and the package path CI takes is never exercised. Pinned by `InputEventCompatibilityTests`, whose reflection is the only thing that can see the difference -- a call binds happily to a longer constructor with defaults, so nothing written in C# can tell them apart. Prefer an **init-only property** for a new field on a record (`ArrangedNode.Depth`, `ClickableRegion.OnPress`, `Node.Grid.ColumnSizing`): it adds nothing to the constructor's identity.
- **AOT compatibility is required** (`IsAotCompatible = true`) — no reflection-based patterns. No native bindings: the font rasterizer is pure-managed.
- `AllowUnsafeBlocks` is enabled in both library and tests
- `RectInt(PointInt LowerRight, PointInt UpperLeft)` — note the unusual constructor argument order (LowerRight first)
- Uses C# 14 `extension` keyword syntax (net10.0 preview features)
- **Codec divorce (4.0+):** DIR.Lib does not depend on any image-codec package. `BoxRasterizer.RenderToRgba` returns an `RgbaImage`; consumers that need TIFF / PNG / JPEG / ICC declare those packages (`SharpAstro.Tiff`, `SharpAstro.Png`, `SharpAstro.Color.Icc`, …) themselves.

**Font dependency:** `SharpAstro.Fonts` is loaded as a local `ProjectReference` if the sibling `Fonts.Lib` repo exists at `../../../Fonts.Lib/`, otherwise falls back to a NuGet `PackageReference`. Controlled by `$(UseLocalFontsLib)`.

**Grammar / parser dependency:** `SharpAstro.LALR.CC` provides a Roslyn source generator that compiles `grammars/latex.lalr.yaml`, `grammars/markdown-inline.lalr.yaml`, and `grammars/markdown-block.lalr.yaml` at build time into partial classes (`Latex`, `MarkdownInline`, `MarkdownBlock`) in this assembly's root namespace. YamlDotNet is a build-only dependency consumed by the source generator (`PrivateAssets="all"`, passed in via `<Analyzer>`); it does not appear in the runtime closure. Like Fonts, LALR.CC switches between `ProjectReference` (sibling `LALR.CC/` checkout) and `PackageReference` via `$(UseLocalLalrCc)`.

## Test Structure

- **Framework:** xunit v3 + Shouldly assertions
- **Visual regression tests** (`RenderAcceptanceTests.cs`, `MathLayoutBaselineTests.cs`, `MathStretchyTests.cs`, `DrawLineTests.cs`, `DrawPolylineTests.cs`): compare rendered output against baseline PNG files in `Baselines/`. Set `DIR_LIB_UPDATE_BASELINES=1` to regenerate.
- **Markdown / LaTeX spike tests** (`MarkdownBlockSpikeTests.cs`, `MarkdownInlineSpikeTests.cs`, `MhchemTests.cs`): exercise the grammar visitors directly.
- **Debug inspector tests** (`DebugInspectorSchedulingTests.cs`, `DebugInspectorDiscoveryTests.cs`, `InspectorOptInTests.cs`) run in Release too (since 11.70): the inspector core (`DebugInspectorCore`, `DebugInspectorRegistry`) is compiled into every build and inert unless the process opts in. `DebugInspectorCore.StartIfOptedIn(host)` starts it only when `DIR_INSPECTOR=1` and `DIR_INSPECTOR_TOKEN` is non-empty (a per-run secret every client request must carry as `token`); the opt-in without a token refuses to start and says why on stderr. `Start` / `Detached` are unchanged. Run the tests with `-c Release` as CI does. The multicast test is skipped unless `DIR_LIB_INSPECTOR_LAN_TESTS=1`, because `dotnet test` hosts the suite in the worktree's own `DIR.Lib.Tests.exe` and binding `0.0.0.0:47892` there makes Windows Firewall prompt once per worktree; run it hosted by `dotnet.exe` (the command is in its doc comment). The registry format those tests pin is the sidecars' contract: `src/DIR.Lib/Diagnostics/inspector-registry.md`.
- **Test fonts** are in `src/DIR.Lib.Tests/Fonts/` — each fixture font has a specific purpose (e.g., Merida is chess-only, subset fonts test PDF embedding scenarios).
- The tests project declares `SharpAstro.Png` directly because the visual tests emit / decode PNG artifacts — DIR.Lib itself no longer pulls codec packages transitively.

## Package Versioning

Central Package Management via `src/Directory.Packages.props` — all package versions are defined there, never in individual `.csproj` files.

This repo's OWN version has **one place to bump**: `VersionMajorMinor` in `src/Directory.Build.props`. Local builds get `Major.Minor.0`; the workflow reads that same property back (`dotnet msbuild src/Directory.Build.props -getProperty:VersionMajorMinor`) rather than restating the number, so CI cannot stamp a version the packages disagree with.

It covers both DIR.Lib and DIR.Lib.Shaping, because CI stamps a single `-p:Version` across them. No csproj declares its own `VersionPrefix` — a per-project one silently overrides the props file, which is how DIR.Lib.Shaping once sat at 6.8.0 while DIR.Lib shipped 7.5.0.

The same version also stamps the **DIR.Lib.Debug** twin: CI packs `src/DIR.Lib` a second time with
`-c Debug -p:DebugTwin=true` (and `-p:GeneratePackageOnBuild=false`, so bin/Debug holds no second nupkg),
because the Release DIR.Lib has the other `#if DEBUG` types but, since 11.70, carries the inspector core itself; the twin stays until its retirement is decided (a follow-up). `tools/debug-twin-check` is a consumer with no
ProjectReference that compiles against that package only (`dotnet build tools/debug-twin-check/DebugTwinCheck.csproj -c Debug`,
after a twin pack into `artifacts/debug-twin`; CI passes `-p:DirLibDebugVersion=<stamped version>`).
`InspectorPackageTests.DebugTwinNupkg_CarriesItsOwnNamedTargets` opens the twin for its targets file. It skips where
no twin is packed, so CI runs it a second time after the twin pack with `DIR_LIB_REQUIRE_DEBUG_TWIN=1`, which makes a
missing twin a failure (11.87; before that it skipped on every machine).

Add the matching entry to [CHANGELOG.md](CHANGELOG.md) at the repo root, in the same commit as the
bump. Newest first, one `## Major.Minor` section each. (The notes used to live in a comment block in
`.github/workflows/dotnet.yml`; nothing ever read them there, and they had grown to 612 of that
file's 674 lines.)
